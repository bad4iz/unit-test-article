# Изоляция ProfilePanel: Shallowly и React Testing Library

Учебный пример к статье «Зачем Shallowly, если есть React Testing Library?». Это маленькая модель зависимостей, а не история про приложение в проде: профиль хранится локально, лента читает синхронный сервис из контекста, запросов в сеть нет.

Нужен Node.js 22 (не ниже 22.12) или 24. Из этой папки:

```bash
npm ci
npm test
```

`ProfilePanel` не принимает входные пропсы. Setup-хук готовит данные для `UserCard` и `ActivityFeed`. Карточке нужен `LocaleProvider`, ленте — `ActivityServiceProvider`.

- `ProfilePanel.shallow.test.jsx`: три сценария родителя с Shallowly. Замокан только setup-хук, среда — Node.js.
- `ProfilePanel.rtl.test.jsx`: те же три сценария с RTL. Setup-хук и оба ребёнка замоканы явно, среда — jsdom. Данные детей проверяются в первом аргументе последнего вызова мока; остальные аргументы вызова React нам не нужны.
- `ProfilePanel.integration.test.jsx`: RTL рендерит настоящие setup-хук и дочерние компоненты. Передаём провайдеры и локальную реализацию сервиса, проверяем получившийся DOM.

В каждом тесте есть явный `mockDefault()` с обычным сценарием. Vitest сбрасывает моки через `mockReset` и восстанавливает подмены через `restoreMocks`. Очистка DOM находится в `vitest.setup.js`; импорт `@testing-library/react/pure` отключает автоматическую регистрацию очистки RTL, чтобы не дублировать её.

Тесты написаны на JavaScript, поэтому используют `mockReturnValue` прямо на замоканных импортах, без TypeScript-обёрток. Колбэки дочерних компонентов в shallow-тестах не вызываются. Замеров скорости в этом примере нет.
