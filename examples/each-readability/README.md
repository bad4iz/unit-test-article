# Читаемость it.each и явных сценариев

Учебный пример на JavaScript и Vitest 4.0.18. `getProfileHeading()` получает профиль из `fetchProfile()`, возвращает заголовок с именем или сообщение об отсутствии профиля. Ошибка источника проходит вызывающему коду. В настоящем модуле источника тоже только локальные данные: сети и приватного кода проекта здесь нет.

Два файла проверяют одинаковые три сценария:

- `src/getProfileHeading.each.test.js` — намеренно неудобная позиционная таблица `[title, profile, error, expected]`; подготовка и проверка ветвятся по `error`.
- `src/getProfileHeading.explicit.test.js` — три явных `it` с прямой подготовкой и проверкой каждого сценария.

Сравнивается конкретная форма тестов. `it.each` здесь не отключён и не сломан: именованные строки таблицы можно запускать по отдельности. Для одинаковой операции над разными данными таблица может оставаться удобной; этот пример показывает случай с разными способами подготовки и разными ожиданиями.

Нужен Node.js 22 (не ниже 22.12) или 24. Из этой папки:

```bash
npm ci
npm test
```

Запуск только сценария ошибки в обоих файлах:

```bash
npx vitest run -t "передаёт ошибку источника"
```

Запуск этого же сценария только из таблицы:

```bash
npx vitest run src/getProfileHeading.each.test.js -t "передаёт ошибку источника"
```

Проверено на Node.js 22.16.0 и Vitest 4.0.18: `npm ci` завершился успешно, все 6 тестов прошли. Фильтр `-t` выбрал 2 теста из двух файлов; вместе с именем файла — одну строку таблицы. Остальные сценарии при этих запусках пропущены.

`mockDefault()` каждый раз создаёт свежий профиль. Служебный сброс реализаций, истории и очередей моков задаёт `mockReset: true`, восстановление шпионов — `restoreMocks: true`. В сценариях нет `beforeEach` или `afterEach`. Каждый тест явно задаёт подготовку и дожидается асинхронного результата.

Тесты подменяют `fetchProfile`, поэтому проверяют работу `getProfileHeading` с подготовленными ответами. Настоящее взаимодействие с сетевым API и производительность этими тестами не измеряются.
