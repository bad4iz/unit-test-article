# mockDefault вместо beforeEach

Запускаемый учебный пример к статье о явной подготовке тестов. `getProfileHeading()` получает профиль через `fetchProfile()`, возвращает заголовок с именем или сообщение об отсутствии профиля. Ошибки источника передаёт вызывающему коду. Источник здесь локальный, без сети и базы данных.

Нужен Node.js 22 (не ниже 22.12) или 24. Из этой папки:

```bash
npm ci
npm test
```

- `getProfileHeading.test.js` проверяет четыре сценария: обычное имя, другое имя, отсутствие профиля и ошибку API. Каждый тест явно вызывает `mockDefault()` в Arrange.
- `mockDefault.js` создаёт свежий объект вместе с вложенным `preferences` и задаёт обычный ответ API. Возвращает этот объект для точечного изменения сценария.
- `mockIsolation.test.js` — отдельная последовательная демонстрация настроек. Первый тест изменяет вложенные данные, вызывает мок и оставляет неиспользованный разовый ответ. Следующий получает свежие данные, обычный ответ и чистую историю вызовов. Такой порядок нужен демонстрации; основные сценарии друг от друга не зависят.
- `getProfileHeading.before.test.js` — исполняемый вариант «до» с внешним и вложенным `beforeEach`. Он проверяет те же обычный и отсутствующий профиль, что и основной файл.

`mockReset: true` в конфигурации Vitest сбрасывает историю, реализацию и очередь разовых ответов между тестами. Сам `mockDefault()` этого не делает: он только готовит данные и обычный ответ. `restoreMocks: true` восстанавливает методы, подменённые через `vi.spyOn`, если такие появятся; модульный `vi.mock` эта настройка не отменяет.

Тесты написаны на JavaScript. Модуль мокается через `vi.mock('./profileApi')`, а ответы задаются прямо на импортированной функции. Бенчмарков и утверждений об ускорении в примере нет.
