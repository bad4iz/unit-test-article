# Почему в JavaScript null >= 0 — true, а null == 0 — false

Перевод с сокращениями и примечаниями статьи Abinav Seelan [Javascript: The Curious Case of Null >= 0](https://blog.campvanilla.com/javascript-the-curious-case-of-null-0-7b131644e274). Пересказ алгоритмов сокращён, названия и ссылки обновлены по актуальной спецификации ECMAScript. Дополнение про `NaN` отмечено отдельно.

Вот три выражения, которые легко сбивают с толку:

```javascript
null > 0;  // false
null == 0; // false
null >= 0; // true
```

Получается, `null` не больше нуля и не равен ему, но при этом больше либо равен. На вид какая-то ерунда. Чтобы разобраться, нужно посмотреть, какие правила использует каждый оператор.

<cut />

У `==` и операторов `<`, `>`, `<=`, `>=` разные правила преобразования типов. А запись `a >= b` не означает, что JavaScript по очереди проверит `a > b` и `a == b`.

## Почему null > 0 возвращает false

В спецификации сравнение порядка описывает операция [IsLessThan](https://tc39.es/ecma262/multipage/abstract-operations.html#sec-islessthan). Для нашей пары значений достаточно трёх шагов:

1. **Получить примитивные значения.** `null` и `0` уже примитивы, поэтому остаются как есть.
2. **Привести значения к числам.** `null` превращается в `+0`, а `0` остаётся нулём.
3. **Сравнить два нуля.** Ноль не больше нуля, поэтому результат — `false`.

Числовое преобразование можно посмотреть отдельно:

```javascript
Number(null); // 0
Number(0);    // 0

0 > 0;       // false
```

По той же причине `null < 0` тоже возвращает `false`: после преобразования один ноль не меньше другого.

Если откроете спеку, встретите названия `ToPrimitive` и `ToNumber`. Это служебные операции из описания языка, а не функции, которые нужно импортировать в проект:

- [`ToPrimitive`](https://tc39.es/ecma262/multipage/abstract-operations.html#sec-toprimitive) получает примитив из объекта, а уже примитивное значение возвращает без изменений. Подсказка `number` задаёт предпочтение при преобразовании **объекта**; для наших `null` и `0` она ничего не меняет.
- [`ToNumber`](https://tc39.es/ecma262/multipage/abstract-operations.html#sec-tonumber) приводит значение к типу Number. Именно по его правилам `null` становится `+0`.

## Почему null == 0 возвращает false

У `==` свой алгоритм — [IsLooselyEqual](https://tc39.es/ecma262/multipage/abstract-operations.html#sec-islooselyequal). Он не приводит любые два значения к числам перед сравнением.

Для `null == 0` происходит следующее:

1. Типы операндов разные: слева `null`, справа число.
2. Правило, по которому `null` и `undefined` считаются равными, здесь не подходит: справа стоит `0`.
3. Правила, которое превращало бы `null` в число при таком сравнении, нет. Алгоритм возвращает `false`.

Разницу видно, если выполнить преобразование явно:

```javascript
null == undefined; // true
null == 0;         // false
Number(null) == 0; // true
```

В последней строке `Number(null)` уже вернул ноль. Поэтому `==` сравнивает два числа. Это другой случай, хотя исходное значение было тем же.

## Почему null >= 0 возвращает true

Для `>=` используется сравнение порядка, а не алгоритм оператора `==`. Проверка `null == 0` здесь вообще не выполняется.

В нашем случае:

1. `null` снова преобразуется в `+0`.
2. Внутренняя операция проверяет, меньше ли левое значение правого. То есть меньше ли ноль нуля. Получается `false`.
3. Получив этот результат, оператор `>=` возвращает `true`.

Для этих значений получается то же, что и при сравнении двух нулей:

```javascript
null >= 0; // true
0 >= 0;    // true
```

Полный алгоритм есть в [разделе спецификации об операторах сравнения](https://tc39.es/ecma262/multipage/ecmascript-language-expressions.html#sec-relational-operators-runtime-semantics-evaluation).

## Почему >= нельзя просто заменить на !(<)

*Примечание переводчика.* Для разобранной пары такое объяснение работает, но переносить его на любые значения нельзя. Вот контрпример:

```javascript
NaN < 0;    // false
NaN >= 0;   // false
!(NaN < 0); // true
```

Если в числовом сравнении участвует `NaN`, внутренняя операция `IsLessThan` возвращает `undefined`: определить порядок нельзя. Это служебный результат алгоритма. Сами операторы `<` и `>=` в таком случае возвращают `false`.

А `!` в последней строке видит только готовый результат `NaN < 0` — значение `false`. Отрицание превращает его в `true`. Поэтому `a >= b` и `!(a < b)` в общем случае не равнозначны.

С `undefined` будет похожая история: при числовом преобразовании он становится `NaN`.

```javascript
Number(undefined); // NaN
undefined < 0;     // false
undefined >= 0;    // false
```

У исходных трёх выражений нет противоречия: `==` и `>=` применяют к `null` разные правила. Но в рабочем коде это легко пропустить. Проверка `value >= 0` сама по себе не гарантирует, что в `value` лежит число. Если `null` означает «данных нет», это состояние стоит проверить явно до сравнения.
